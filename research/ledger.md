## 1. Process (what another agency would repeat)

Legend: **[G]** general — the step and its code carry over unchanged. **[AS]** agency-specific in
implementation (file formats, conventions, people), general in the problem it solves.

1. **Data pull [AS].** One-time pulls of the controller hi-res event log (public data-logger event
   enumeration) for every signal: 72 h (Dec-2024, 421 signals), a 6 h statewide slice of six codes
   (Feb-2025, 958 signals), ~66 h (Sept-2026, Fri 16:15 – Mon 10:24, two-thirds weekend) and a later
   7-day pull of which ~3 days were available (late Sept-2026). Plus the controller timing database
   (per channel: call phase, call overlap, switch phase, additional call phases, delay/extend) and the
   hand-maintained detector config export. No polling; everything heavy on a local work disk.
2. **Event filtering [G].** Keep only codes 81/82 (detector), 1, 7, 8, 9, 10, 11 (colour), 43/44
   (phase call), 131/150 (coordination), 173 (flash); drop `Parameter > 64` on 81/82 (dummy
   detectors); `SELECT DISTINCT` first (~2 % of detector rows are exact duplicates; ~+0.5 pt, note 01).
   Fault codes 83–88 were later removed from everything (user, 2026-09-28; notes 38, 48). Six codes
   (1, 7, 43, 44, 81, 82) carry ~all the phase signal (note 05); 43/44 alone are worth 10–22 pt.
3. **Problem framing [G].** Phase-anonymous: the model scores each (detector, candidate phase) pair
   from behaviour only; candidates = every phase with a Begin Green in the sample; answer = a
   normalisation over candidates. No phase or channel number is ever an input; `model/check.py`
   renumbers phases to prove it. Overlaps are not predicted (no overlap call event; note 10).
4. **Labels and their evolution.**
   * (a) Hand config export [AS] — phase + function strings mapped to classes (notes 01, 05, 06, 11).
   * (b) Official controller timing as PHASE truth (`call_phase`, else `call_overlap`) [AS source,
     G idea]: +41 % labelled channels, +0.27 pt; hand vs timing agree 97.24 %, stable over 21 months
     (note 10). Scorer also credits `switch_phase` / `additional_call_phases` (note 14).
   * (c) Engineer corrections of confident model-vs-label misses [G]: 37 of 79 function labels on the
     exam signals were wrong (note 14); a separate phase-suspect list (note 22).
   * (d) Cabinet-print mining [AS]: scripted PDF text pass + ~1 min visual read per signal of the
     intersection diagram / input file; confidence tiers; high-confidence print label overrides the
     hand label (never "only where the model agrees" — circular); at print-complete signals every
     unexplained active channel is labelled Other (notes 23, 26, 27, 34–36).
   * (e) Behaviour validation (cleansing) [AS thresholds, G rules]: every training label checked
     against the engineer's physics (presence holds the call through red at peak, count off in red,
     advance leads the stop-bar zone, mid ≈ sum of advances, bike far below vehicles, card and
     health checks, permissive-phase and right-turn exemptions); fail / unhealthy / misconfigured
     rows are not trained on (notes 24, 29, 44), health-bad periods removed (note 45).
   * Two layers (user, 2026-09-24): cleansing may use prints, technology, lanes, card structure; the
     MODEL sees only the hi-res log.
5. **Evaluation protocol [G].**
   * Locked hold-outs: 43 TEST + 143 NEWTEST signals, never trained or tuned on; opened once for
     final_v1 and once for final_v2 (notes 12, 13). From 2026-09-24: 115 locked (43 TEST + 72
     NEWTEST); a seed-fixed, region-stratified random 71 NEWTEST released to training (note 36).
     Locked-signal print labels are labels only — no scoring.
   * Model selection on six signal-grouped folds (fold 0 = the 2025 model's own 38-signal hold-out);
     frame extensions add signals without moving any (`folds_v3`, `folds_v4`).
   * One model for all sample lengths: trained on a 22-window mix (4×5 min, 4×10 min, 4×30 min,
     3×1 h, 2×3 h, 2×6 h, 2×24 h, full); reported at 5 min / 30 min / 6 h / full.
   * Headline = detectors with ≥ 5 actuations whose labelled phase turns green in the window;
     unscorable counted and reported separately; coverage given with every number.
   * Two-number scoring (user-approved 2026-09-29): "everything" (all labelled, only the ≥ 5-actuation
     rule) and "realistic" (minus rows the label checks call wrong/misconfigured). A cleansed
     clean-label subset overstates gains (~1.2 pt, note 45) and is labelled optimistic.
   * Noise floor: seed spread ±0.07 pt (trees), 0.1–0.45 pt (network); ≥ 2 extra seeds and a
     shuffled-label or noise-column control for any new feature family; paired signal-bootstrap CIs.
     Screening bar: ≥ 0.3 pt phase at 30 min, ≥ 1 pt function; below the bar = dropped, not tuned.
6. **Shipping [G].** numpy-only inference (LightGBM trees re-evaluated in numpy to 0.0 difference),
   network via ONNX Runtime on CPU; `check.py` = reference reproduction + phase-renumbering invariance
   + blocked torch/lightgbm/scipy/sklearn.

Abbreviations: OOF6 = six-fold signal-grouped out-of-fold; F0 = fold 0; "blend" = 0.5 trees + 0.5
network probabilities before the joint decoder; A/P/C = Advance/Presence/Count; core-four = A/P/C/YR;
acc7 = 7-class (A, P, C, YR, Mid, Bike, Other); CIs are 95 % paired signal bootstrap unless the row
says 90 %.
